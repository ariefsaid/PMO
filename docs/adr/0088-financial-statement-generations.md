# ADR-0088 — Financial statement generations and scoped reads

**Date:** 2026-10-16 · **Status:** Proposed (implementation plan for #897)

## Context

The signed `docs/specs/financial-statements.spec.md` requires ERPNext v16.33.0 report parity, two comparison columns from one complete source, current-chart restatement, and project totals without account detail for project staff. Existing seams are `ledgerFetch`, `ledgerMirrorFeed`, the ERP sweep, repository/DAL reads, and the accounting snapshot UI. A transaction publishing results does not by itself make a multi-page source read coherent.

## Decision

1. **Version the source, not just the result.** Add `erp_account_mirror` (unique org/company/ERP name), `erp_financial_statement_generation` (company metadata, fiscal calendar, chart, settings, source fingerprint, completion flags, lease epoch and refresh outcome), and `erp_financial_statement_source_line` (generation-pinned ledger rows). Retain decimal strings in source JSON; widen mirrored company-currency debit/credit to unscaled `numeric`. All have `org_id`, RLS, explicit grants and denominator entries. Generation/source-line reads are machine-only. Account scans are complete and paginated; missing/renamed/merged names require a full company-ledger replay and exact reference reconciliation. No inference from account names/numbers.
2. **Fence writers and freeze input.** A service-only, company-scoped lease with monotonically increasing epoch fences every ledger page write and completion. Resume bounded backfills using a compound source cursor; partial or failed work cannot certify completeness. Capture the completed mirror into immutable source lines with one database transaction, using text serialization of numeric values. Save the complete chart and source metadata with that generation. Restart when source verification changes. Lease expiry never authorizes a stale worker's writes or publication.
3. **Aggregate once on the server.** Deno/Vitest-importable TypeScript implements the pinned standard-report profile over the frozen ledger, using exact decimal arithmetic and upstream report rounding boundaries. It computes supported month/quarter/fiscal-year pairs for the captured calendar, company statements, mapped-project P&L, and the unassigned remainder. Account Closing Balance is an independent oracle, never a locally manufactured source. No Payment Ledger, estimated recognition, currency conversion or accounting posting supplies amounts.
4. **Publish one complete result set.** `erp_financial_statement_snapshot` stores one row per statement/scope/view/period pair, with both columns in one validated payload, decimal-string amounts and immutable provenance. Service-only staging/publication RPCs validate bounded output chunks against the complete expected-scope manifest, org/company/generation/epoch, account references and payload shapes; under the company lock publication replaces the entire company's result set in one transaction and advances the published generation. Stale/failed attempts leave the previous payload and original `as_of` intact. Refresh status is separate from result time. Retain published source plus an in-progress candidate; collect unreferenced generations only after publication.
5. **Keep aggregate access narrow.** Active own-org Admin/Finance/Executive may read account master, both ledger mirrors and account-breakdown statements. Project staff may read only project-total snapshot rows for projects visible through existing project RLS. The read RPC is **security invoker**, rechecks active membership/org/role/project visibility, accepts no org/company/generation override, and constructs a whitelist DTO. Project payloads contain only income/expense/net, dates, IDR and safe provenance; no filters/settings/chart or raw ERP project identifiers. An explicitly own-org/active/role-filtered security-barrier view exposes only safe availability/calendar metadata to invoker reads, never the machine generation body. No ordinary-user write path exists to any read-model. Client permissions/cache keys use the real role; RLS remains authoritative.

## Consequences

Extra source storage and a copy per completed refresh buy reproducible, page-safe aggregation and bounded rollback. Indexed org/company/generation scans, pre-indexed period sums, bulk publication and prompt collection avoid per-account queries and unbounded history retention. New migrations start at the next verified slot (`0294` at planning time), each with a rollback file. AC-001 proves synthetic parity; AC-003/004/006 prove SQL access/publication; AC-002 remains a required private read-only rehearsal. OQ-002 is unresolved: full-ledger equivalence to the ERP closing-balance path must pass before acceptance; a mismatch leaves statements unavailable rather than adding a balancing amount.
