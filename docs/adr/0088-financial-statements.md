## Context

The signed `docs/specs/financial-statements.spec.md` requires ERPNext v16.33.0 standard-report parity, complete account/ledger refresh, two comparison columns published atomically, current-chart restatement and totals-only project reads. It does not require a durable source-generation subsystem. Scale is one company with about 1,300 ledger lines over two years, refreshed every five minutes; design for 100× (130,000 lines), not a distributed ledger.

The inspected `runErpSweepCycle`/HTTP wiring in `supabase/functions/erpnext-sweep/index.ts` and cron helper in migration 0102 do not serialize overlapping per-org cycles across feed and aggregation. The production writer search, bounded to `supabase/functions/`, `pmo-portal/src/` and migrations, locates the ledger feed writes in `ledgerMirrorFeed.ts`, invoked by the sweep. Recheck that inventory when building. A short RPC transaction lock cannot span subsequent ERP HTTP calls or TypeScript aggregation.

Migration 0101 defines GL debit/credit as numeric(14,2); inspected migrations through 0293 do not alter those types. ERPNext's pinned GL Entry metadata declares both as Currency; Frappe v16's Postgres/MariaDB Currency mapping supports decimal(21,9). Two-decimal storage therefore loses supported fractional precision, irrespective of IDR display precision. This does not assert that live rows contain such fractions; rehearsal must record actual source revision/settings/precision.

## Decision

1. **One writer, one tick, one org lock.** The sweep alone writes ledger mirrors and `erp_account_mirror`. At org-cycle start reserve one session-capable PostgreSQL connection and call `pg_try_advisory_lock` with the org-scoped `erpnext-sweep:` key. If held, skip this org's tick; continue other orgs. Keep the lock through chart/ledger feed, stable mirror reads, pure aggregation and publication; unlock/close in finally. Use the same reserved session for mirror/watermark/status mutations and publication, under service_role, with no reconnect/retry. Connection death releases the lock and prevents that worker from performing later writes. No transaction spans HTTP/TS work, transaction-pool session locks, or PostgREST acquire/release pair. The function-local pinned database driver and private runtime connectivity are implementation dependencies, not a new public API. While the sweep aggregates, no other local writer can change its mirror, so **no frozen copy is needed**. Ceiling: **"ponytail: single-flight sweep; if refresh outgrows one tick, move to generations"**.
2. **Full chart, simple replay flag.** Fully scan accounts every sweep, including disabled historical accounts; validate before upserting the chart. Mirror all signed account fields; a run UUID on accounts supplies provenance, not a generation-table FK. A missing chart name referenced by uncancelled company GL sets an org `statement_full_ledger_replay_needed` flag on the existing binding. The **next sweep** replays all company GL without a modified watermark, including unchanged linked rows after rename/merge, and reconciles obsolete names only after every page succeeds. Initial migration sets the same flag to require historical backfill of explicit company/is_opening/finance_book and widened GL numeric values. Failed replay restarts from the beginning; unresolved references block publication. No guessing accounts, partial-history promotion or durable compound cursor. Moved accounts restate both columns under the current chart. Ordinary incremental feeds keep their existing watermark.
3. **Small source/status footprint.** Add only `erp_account_mirror` and `erp_financial_statement_snapshot`. Use four simple columns on the existing binding for replay needed, delayed, last attempt and safe supported calendar dates; no settings/credential/source inventory body there. Detail snapshots retain exact report filters/settings/version; totals rows do not. Widen **only GL debit/credit** to unscaled numeric because the current two-decimal scale cannot retain ERP's supported precision. Preserve raw decimal tokens through transport, SQL numeric-as-text and aggregation; leave unrelated amount sources alone. Retain cancelled rows but exclude them from statements. Single-flight establishes local source stability, not a snapshot of a concurrently changing ERP; incomplete/error feeds and changed chart/settings/calendar defer publication.
4. **Pure aggregation, one atomic publish.** After a tick's chart and ledger feed explicitly complete without error and replay/account references are resolved, run the same Deno/Vitest-importable pure TypeScript aggregation tested by AC-001 over the stable mirror. Compute every supported month/quarter/fiscal-year pair, all company statements, mapped-project P&L and finance-only remainder; use exact decimals/upstream report rounding, indexed buckets and hierarchy rollups. Call **one service-only publication RPC** with the complete in-memory output. Under the org advisory lock, validate activated company, org/project scopes, both columns, complete finite calendar/map coverage and payloads; reject duplicate/missing/older replacements, then replace that org+company's snapshot rows and clear replay/delayed status in one transaction. No staging chunks, durable expected-scope manifest or separate capture/claim/resume/collect RPCs. A snapshot/source run UUID satisfies signed generation identity without a source lifecycle table. Any failure retains the old rows and original as_of, with **Update delayed**; first absence is unavailable, not zero.
5. **Keep scoped reads and existing UI seams.** Active own-org Admin/Finance/Executive read accounts, both ledgers and statement detail. Project staff read only whitelisted income/expense/net totals for projects visible under existing projects RLS, including on direct snapshot SELECT. Detail-only provenance columns are null on totals rows. SECURITY INVOKER catalogue/read RPCs recheck active membership, real role, org and project visibility; no client org/company/source override. A narrowly filtered security-barrier availability view projects only safe dates/status/provenance, never the binding body. RLS/grants are authoritative; client permissions/cache isolation use the real role. Retain the repository/DAL seam, company statements page, project Overview totals, shared Card/DataTable/ListState/provenance, both locales and honest states.

## Consequences and gates

This trades durable mid-refresh resumption/reproducible source copies for a straightforward single-writer invariant and cheap whole-replay retry. Existing snapshots remain readable during source updates and transactionally switch only on complete success (AC-006/FR-008). Memory, HTTP calls and one publish request must fit the actual deployed Deno limits at 130,000 synthetic lines with the complete period/scope catalogue. Use paged/bulk access and measure; budget exhaustion fails closed. If that target cannot fit one tick, return to Director under the stated ceiling, not silently reintroduce a distributed protocol.

AC-001 independently oracle-tests every amount/key; AC-003/004 prove actual role/grant/RLS/invoker access; AC-005 proves chart/replay failures and restatement; AC-006 plus real two-session overlap tests prove atomic/concurrent publication and single-flight. Keep denominator entries for both new tables/functions/read surfaces and reversible migrations with guarded numeric narrowing. AC-007..009 retain the UI/scope/cache proofs. The revised plan has **35 tasks in five PR batches**.

AC-002 remains a required **private read-only rehearsal**, with before/after ERP source validation, every account/subtotal/total/comparison and real Finance UI totals. OQ-002 remains open: independently prove complete historical-ledger equivalence to ERP's Account Closing Balance path before enabling publication for that rehearsal source. This is a Director release checkpoint, not a durable database readiness-witness subsystem. Do not change ERP settings, post/close, accept a balancing plug or publish live evidence. The signed spec remains unchanged.

Removed: `erp_financial_statement_generation`, leases/epochs, durable compound cursors, `erp_financial_statement_source_line`, frozen copies, staging chunks, stored expected-scope manifest, claim/resume/capture/collect RPC family and source GC. **No removed mechanism is required by an AC**: their required outcomes are covered by single-flight, the replay flag, complete pure aggregation, atomic replacement and private reconciliation. Future multi-tick refresh is explicitly deferred.
