`/procurement` (collection): title + own/team scope → search → status/project filters → visible “Newest requests” sort (oldest requested first in Needs approval) → Table/Board → More (export/import/cycle import, ERP evidence link) → **Raise request** → rows. `/procurement/new` (capture): named return → title + draft/project/currency scope → title/project/category → optional vendor disclosure → line items with exact net total → inline errors/recovery → Cancel + **Save draft**. No header Save; no fake wizard. Partial save retains saved request and only unsaved lines for retry (E-01–04).
`/procurement/:id` and `/:tab` (record): identity + current status/date + project/requester/vendor scope → section navigation → Review: distinct request/quote/order facts, budget evidence and items needed for the decision → notes/reason + **eligible next transition** after evidence. Items edits lines; Documents holds ledger/capture, linked ERP evidence and files/references; Quotes compares bids before selection; Activity holds dated changes. Only the active capture/decision owns the filled primary; Edit/Reject/Cancel remain quieter.
`/erp-purchases` (collection, Procurement child): return → title + unlinked-evidence scope → search → project/type filters → “Latest document date” → selection tools → documents. No creation primary at rest; **Link selected documents** appears only with selection; New purchase from selection stays secondary. Single-row Link opens the same dialog; document identity names the source; Link opens the evidence-and-purchase chooser, and a successful result opens the canonical purchase.
`/expenses` (collection): title + own/team scope → search → status/type/category/project filters → “Newest claims” sort → Claims and advances / Outstanding advances view → Request advance (secondary) → **New claim** → one row set. Outstanding view sorts oldest paid date first (unknown dates last), with age and outstanding replacing claim amount; no duplicate aging dashboard above it.
`/expenses/new` (capture): return → title + inherited project/currency scope → optional receipt + first line (date/type/description/amount) → additional lines → title/category/purpose/advance details (named disclosure; project remains visible) → amount → inline recovery/errors → Cancel + **Save draft**. Receipt is optional, never silently classifies type; expose title/category suggestions with their source, preserve explicit edits (E-01–04).
`/expenses/:claimId` (record): identity/status + claimant/project/category scope → purpose + amount/paid split or outstanding + linked advance/rejection reason → lines (claim only) → receipts → approval routing + **eligible submit/approve/pay/return** after evidence → disclosed Accounting activity. Edit is secondary; paid/closed records have no invented next action. Return/payout amounts and confirmations keep existing rules.
