## Decisions and critique

These are recomposition decisions, to be implemented together; this docs delivery does not change navigation. No route retirement is necessary because the PA-00 table names a real outcome for each. Do not preserve a block merely because its route stays.

| Decision | Who/trigger/wrong outcome addressed | New home and retained access | Rule |
|---|---|---|---|
| KEEP `/views` and renderer | Any role repeatedly asks the same owned or shared scoped question; removing saved answers makes them rebuild work every visit | Existing canonical `/views/:viewId`, shell utility, all saved definitions intact; no extra portfolio tiles elsewhere | PA-00, N-04 |
| KEEP both builder URLs; simplify panel language | Owner configures recurring answer; exposing primitive/entity/column-span equally with question and scope makes the build task harder to recognize | Same URLs; business-facing labels “Display”, “Records”, “Fields”; query and layout settings in named Advanced disclosure; retain supported controls, limits, preview, private/shared choice and AI draft review | PA-00, E-03 |
| KEEP incidents list/detail | Any member reports an unlinked organization event; a project-only home would make this report impossible to place | Existing `/incidents` register and record URLs, optional Project, existing feature eligibility; no new schema/workflow | PA-00, E-01 |
| KEEP contacts and companies separately | PM knows a person's name but not their company, or Finance knows account but not person; forcing both through one hierarchy adds a needless search | People directory + account directory; company Contacts list and person Company link connect canonical records | PA-00, N-04 |
| RETIRE “Primary contact” block | PM arriving at account may treat an alphabetical first contact as a business designation; no persona can finish choosing a designated contact from that fact | All contacts retained in account Contacts section and person directory; no invented primary designation | PA-00, PA-03/04 |
| RETIRE Contacts meeting promotion | PM looking for a person needs contact methods, not a module advertisement | Meeting participation links remain in the person's Activity timeline and global Meetings | PA-00, PA-04 |
| MERGE duplicated record fields | Incident reviewer and account reader must reread identity/type/status/date in header and detail | Put each fact once in title/scope; body retains location, description, legal/display-name distinction and optional numbering | PA-03/04 |
| MERGE approval presentations | Reviewer choosing All currently scans procurement/time preview plus separate expense/invoice sections | One typed list and selected evidence adapter for all eligible kinds; existing confirmations, reasons, invoice/claim links, bulk timesheet mode and exception remedies survive | PA-03, A-01/02 |
| MERGE timesheet rollup | Staff sees hours-this-week above grid, grid grand total, footer/phone action variants | One week total per active layout in grid footer with adjacent submit; daily and per-project totals retained as different facts | PA-04, A-02 |
| MERGE meeting save surfaces | Author edits date and minutes in one sitting; separate filled Save meeting/Save minutes split the completion job | Explicit edit session with one Save meeting after evidence; preserve partial-save recovery and dirty guards; read view has one Edit meeting primary for author/Admin | A-01/02, E-04 |
