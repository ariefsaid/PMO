## Migration 1395: `task_groups` and `tasks.task_group_id`
- `task_groups (id uuid pk, org_id uuid not null default 00000000-0000-0000-0000-000000000001 references organizations,
  project_id uuid not null references projects on delete cascade, name text not null check (length between 1 and 120),
  sort_order int not null default 0, milestone_id uuid null, archived_at timestamptz null, created_at)`.
- Unique `(project_id, id)`; composite FK `(project_id, milestone_id) -> project_milestones(project_id, id)`
  `on delete set null (milestone_id)` (pattern of 0202). Index on `(milestone_id)`, `(org_id)`, `(project_id)`.
- `tasks.task_group_id uuid null`; composite FK `(project_id, task_group_id) -> task_groups(project_id, id)`
  `on delete set null (task_group_id)`; index.
- RLS enabled and forced: select `org_id = (select auth_org_id())`; write PM and Admin with the parent-project org
  guard (shape of `project_milestones_write`, helpers wrapped `(select ...)`).
- Extend the task column-pin trigger (`enforce_assignee_status_only`, current body to be read at head first) so an
  assignee and an externally-owned task cannot change `task_group_id`.
- Fragment `scripts/isolation-probe-denominator.d/2679-task-groups.json` for the new org_id table.

## Migration 1396: roll-up in the two read RPCs
Re-create `get_project_milestones(uuid)` (body of 0145) and `get_projects_delivery(uuid[])` (live body of 1142, copied
verbatim) with one change: the task join becomes
`left join tasks t on (t.milestone_id = m.id or t.task_group_id in (select g.id from task_groups g where g.milestone_id = m.id and g.archived_at is null))`
(written as an exists to stay de-duplicated and index friendly), keeping the parent and archived filters. Security
invoker, same grants and revokes.
