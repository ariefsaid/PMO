## Shared interaction design

- Use a typed URL-state codec with a per-list schema from the spec's query vocabulary. The URL is authoritative for supported keys; existing session-stored view preferences are the fallback and are materialized into the effective list URL. Use history `replace` for edits, preserving unrelated query keys. Reject invalid enum tokens; retain a syntactically valid but unavailable referenced ID as a clearable zero-match selection. Keep the existing `?filter=` and `?status=` dashboard meanings and role defaults.
- Keep record URLs at their current canonical path. Send a small typed return context through React Router `location.state` when the user opens a record. Validate its path against an exact allowed list route, bound to the record type; do not accept an absolute URL or an unrelated internal path. The Projects breadcrumb remains Projects. The existing persistent PipelineLens Sales link reads Sales context if present and otherwise uses bare `/sales`.
- Capture `main-scroll.scrollTop` before the drill. Its shell effect currently scrolls to zero on pathname changes, so restore only after the list's rows settle. For native browser Back, store the offset in the source history entry's per-tab state keyed by the React Router location key; for explicit return, carry it in the return navigation state. Clamp to the rendered scroll range and use top if unavailable. Do not restore a stale offset on a fresh direct list visit.
- Preserve record and list permission behavior, existing mutation destinations, and stage/tab route semantics. On archive success, a return to the filtered list may no longer match the archived record; preserve the list controls and show the resulting set truthfully.
