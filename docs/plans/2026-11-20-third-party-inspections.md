## Design summary
- One table `third_party_inspections` holds the tracker. Status moves only through RPCs (`SECURITY DEFINER`, `assert_is_active_member`, role and org checks in the body, as `create_purchase_request`). Direct insert/update on `status`, `procurement_id`, result and waiver columns is not granted; a trigger also refuses skipped steps so no writer bypasses the RPC.
- Cost is not stored. `estimate` is a planning figure only: it never posts cost, is not copied into any purchase record and is in no total. `procurement_id` links one case. The cost view sources from the shipped `public.work_order_cost_lines` (0951 §6; columns `source, record_id, org_id, project_id, work_order_id, discipline_id, occurred_on, reference`, no money, no case id, security_invoker): keep lines for the inspection's `work_order_id` with `source in ('purchase_order','vendor_bill')`, join `record_id` to `purchase_orders` / `procurement_invoices`, keep those whose `procurement_id` equals the inspection's, and sum `amount` per `currency` (voided and ERP-cancelled bills excluded, as 0999 does). Money is visible to Admin, Executive, Finance, Project Manager (the roles of `work_order_cost_amounts`, 0999). An actual-paid figure, if shown, is a join to `work_order_cost_amounts(project_id)` on `record_id`, never recomputed here. No new cost writer.
- **Nesting (read, 0951 §5):** `set_cost_attribution(p_source text, p_ids uuid[], p_work_order_id uuid, p_discipline_id uuid) returns integer` is `SECURITY DEFINER`, `auth.uid()` is read from the request claims, so inside another definer RPC it still sees the human caller. It calls `assert_is_active_member()`, requires `auth_org_id()`, accepts `p_source` in `purchase_request`, `purchase_order`, `goods_receipt`, `vendor_bill` (plus timesheet_entry, stock_document, equipment_usage), 1..500 ids of the caller's org (another org reads as absent, `P0002`), and lets Admin, Executive, Finance, Project Manager change any record of their org in any status (others only their own requested records). It sets BOTH columns (null clears), so the raise RPC must pass each record's existing `discipline_id`, never null. The `zz_cost_attribution_check` trigger then enforces own-project, own-org and not-cancelled (`COST_WO_*`, `23514`). **It can be nested; the raise RPC calls it directly.**
- Report files follow `purchase_request_files` (0036: columns `id, org_id default seed org, <parent>_id references ... on delete cascade, title, file_path, uploaded_by_id, created_at, archived_at`; partial parent index on `archived_at is null`; `enable` + `force row level security`; select policy `org_id = auth_org_id()`; a `BEFORE INSERT` org-stamp trigger copying `org_id` from the parent when null or at the seed default; write policy with the parent-in-same-org `exists`). Two deliberate differences: the parent FK is `on delete restrict` (inspections are archived, never deleted), and the write role set also admits the Engineer, because the Engineer reports from the field. **Engineer scope (OD-TPI-7):** no shipped project-membership helper exists (searched `supabase/migrations` for membership tables and `is_*`/`can_*` project helpers; `projects_select` and `work_orders_select` are `org_id = auth_org_id() and is_active_member()`, and `tasks_insert` / timesheet writes admit Engineer org-wide), so the Engineer predicate everywhere (RPCs, files-table write policy, storage write policy) is the same org-level form: `org_id = (select auth_org_id()) and (select is_active_member()) and (select auth_role()) = any (array['Admin','Executive','Project Manager','Finance','Engineer'])` (per the RLS initplan rule of 0646: caller functions wrapped in `(select ...)`), with the inspection's org checked by `exists`. **Bucket: a new private bucket `inspection-reports`** (15 MB, PDF / png / jpeg / webp / Office MIME list of 0028), not `procurement-files`, whose limit is 5 MB (0028 §4) and whose write policy admits only Admin / Executive / Project Manager / Finance and requires segment 2 to be a procurement (0028 §5; 0350 narrows it further). Storage policy pattern, as 0028 §5 and the once-per-query form of 0696: path `{org}/{inspection_id}/{file_id}/{filename}` (4 segments); select = `auth.uid()` set, segment 1 = `auth_org_id()`, `is_active_member()`; write (insert only, no update or delete policy) = the same plus segment 2 is an inspection of the caller's org on which the caller may advance. The 10-file cap and append-only after `reported` are enforced by table triggers, not by storage.
- Prerequisite read `work_order_inspection_prerequisites` is a stable security_invoker function consumed by #2522 / #2576.
- Overdue sweep: SQL function plus the existing scheduled-notification path (as FR-EAV-009 / document expiry), writing `notifications`.

## Migrations (numbers assigned by the Director; each has a rollback file; RLS + force RLS; `org_id` default / `stamp_org_id`)
- **Migration A (tracker + files):** `third_party_inspections` (org, project stamped from the work order, work_order_id not null, section_id uuid null `check (section_id is null)` until #2576 drops the check and adds the composite FK, title, test_kind, vendor_company_id, planned_on, estimate, currency, required_for text[] check subset of readiness|billing, status check, result check, procurement_id null unique, dates per step with actor columns, cancelled_reason, waiver_reason/by/at, archived_at, created_by) + `third_party_inspection_files` (inspection, storage path, name, size, type, uploader; org copied from the inspection, `on delete restrict`); indexes `(org_id, work_order_id)`, `(org_id, project_id, status)`; trigger refusing direct status writes and skipped steps, and a guard that `project` equals the work order's project; trigger making report files append-only after `reported`; add the **inspection table only** to `record_history_config` (file rows are append-only, not a tracked entity) and bump the catalog gate's hard-coded entity count from 17. Rollback drops both tables and triggers and removes the registry row.
- **Migration B (step RPCs + prerequisite read):** `inspection_create`, `inspection_advance(id, to, payload)`, `inspection_cancel` (refuses `TPI_CANCEL_REQUIRED` when `required_for` is non-empty; a tracked-only inspection may be cancelled by its creator while `requested` or by a manager), `inspection_waive` (refuses with `TPI_WAIVE_SELF` when `auth.uid()` equals the inspection's `created_by`, and `TPI_WAIVE_NOT_REQUIRED` when `required_for` is empty; reason mandatory; roles Admin / Project Manager / Finance; the waiver columns have no direct grant and a trigger refuses direct updates of them), `work_order_inspection_prerequisites(...)` (section_id must be null until #2576), with grants revoked from public and anon. Rollback drops the functions.
- **Migration C (purchase link + cost read, money):** `inspection_raise_purchase(id, link_procurement_id default null)`, `SECURITY DEFINER`, `assert_is_active_member`, role in Admin / Project Manager / Finance, inspection in `requested`, row locked. Create path: calls `public.create_procurement_with_items(p_id uuid, p_header jsonb, p_items jsonb) returns procurements` (0449; header keys limited to `title, project_id, vendor_id, budget_category, is_subcontract`; `p_id` derived from the inspection id so a retry is idempotent; empty `p_items`); it requires the `procurement` feature and writes the procurement and intent rows itself. The inspection never writes a procurement, purchase request or purchase order row, and does NOT call `create_purchase_request(p_procurement_id uuid, p_reference_number text, p_status text, p_date date, p_amount numeric, p_import_key, p_import_batch_id, p_imported_at, p_external_ref)` (0793) or `create_purchase_order(p_procurement_id uuid, p_reference_number text, p_status text, p_date date, p_amount numeric, p_import_key, p_import_batch_id, p_imported_at, p_external_ref)` (0712): procurement's own Draft-to-Requested transition creates the request, and orders and bills come from procurement. Link path: validates the case (same project and org, held by no other inspection, records naming no other work order) with the `TPI_*` refusals, then calls `set_cost_attribution` once per source (`purchase_request`, `purchase_order`, `goods_receipt`, `vendor_bill`) passing each row's existing discipline. Also a `BEFORE INSERT` trigger on the four record tables (`purchase_requests`, `purchase_orders`, `procurement_receipts`, `procurement_invoices`), named to sort before `zz_cost_attribution_check` (e.g. `a1_tpi_fill_work_order`; BEFORE triggers fire in name order, so `check_cost_attribution` validates the filled value), that sets `work_order_id` only when it is null AND the row's `procurement_id` is linked from a non-cancelled `third_party_inspections` row; it never overwrites a set value and writes no other column (FR-TPI-021, OD-TPI-6). It changes money-path tables, so it ships in Slice 3 alone. View `third_party_inspection_cost` as described above. Rollback drops the function, trigger and view and leaves the cases untouched.
- **Migration D (overdue):** `inspection_overdue_sweep(as_of date)` writing `notifications` once per inspection and recipient (idempotency key in `metadata`). Rollback drops it.
- ADR candidate: "Inspections link to procurement rather than carry cost" (reuse of the cost path; cost never stored on the tracker). Write the ADR only if the owner confirms OD-TPI-1.
