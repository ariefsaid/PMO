# Plan: UX wave 2c — phases (UXS-034, UXS-035)

## Scope and design

Implement the signed `docs/specs/ux-wave-2c-phases.spec.md` and DD-VOCAB-1 as a presentation-and-localization-only slice. User-facing delivery work uses **Phase** in English and **Fase** in Bahasa Indonesia; TypeScript interfaces, component filenames, `project_milestones`, `milestone_id`, RPCs, repository/DAL calls, permissions, and URLs retain `milestone`.

The existing data flow remains unchanged: `MilestoneStrip` reads `MilestoneWithProgress` from `useMilestones`, the form sends the existing `MilestoneInput`/`MilestonePatch`, and `ProjectCalendarView` receives the one batched `MilestoneDate[]` read. Only rendered copy and the calendar’s phase-chip presentation change. In particular, do not add `input_pct` to create payloads, alter the weight-weighted rollup, ordering, query/RPC shape, cache keys, DB schema/RLS, or project routes.

The form will use the shipped `TextField.helper` affordance for weight and position so help is visible and programmatically associated with each input. Its progress explanation stays visible in both modes: it is the edit override field’s helper in edit mode and a full-width muted explanation in create mode, where no override field exists. This tells a user what will happen without changing the create model. Calendar phase chips will put project name first (`Project name · phase name`), which preserves project scent under narrow-chip truncation; their localized accessible name will also state the project and Phase/Fase.

No migration, DAL/repository/hook, route, cache, or ADR is needed. DD-VOCAB-1 is the already-approved retained vocabulary decision.

### UI constraints

- Retain the existing calm near-mono `DESIGN.md` surface, 32px controls, shared `EntityFormModal`/`TextField` primitives, global focus ring, and responsive calendar grid/agenda split; do not introduce a card, color, icon, or motion treatment.
- Form help uses the existing 12px `text-muted-foreground` helper style and remains visible rather than placeholder-only. The single primary form submit remains unchanged.
- Preserve the calendar chip’s existing button semantics, project-opening callback, token-only secondary surface, and keyboard focus behavior. Project identity must be the visible leading text, not hover/title-only metadata.
- The existing `scripts/prior-art.sh 'milestone phase calendar'` sweep was silent only across its five searched sources; DD-VOCAB-1, the signed spec, and Discover B B-10/B-13 decide this work.
