## Design contract (shared across all batches)

### Source generation and publication

The sweep remains the scheduler. Sequence for each activated company:

`claim/resume generation → full chart + metadata scan → ledger feed/backfill → verify source → freeze mirror → aggregate immutable generation → atomic publish → collect unreferenced source`.

- A company-scoped lease lives on `erp_financial_statement_generation`, with an increasing **epoch**, expiry and durable compound cursor. Every page write, completion and publish verifies epoch/lease under the same transaction-level company advisory lock. Lease takeover invalidates the old worker; do not hold a DB transaction open across HTTP. A partial tick resumes the same candidate. Failed work records only a safe outcome code; result `as_of` never becomes failure time.
- Full chart scan at activation/first sweep, then each five-minute sweep; do not wait for an Account `modified` delta. Store complete chart/settings/calendar/project-map fingerprint on the candidate. Missing/renamed/merged account identity forces a **full company-ledger replay from the beginning**, including linked rows with unchanged `modified`; moved parents require full report restatement. Exact references, never string similarity. Keep disabled historical accounts. Unknown account, orphan/cycle/invalid nested-set range, ambiguous project map, missing fiscal metadata or incomplete source blocks completion.
- First source for this schema version must historically backfill **all** ledger lines, not resume an earlier feed watermark. New `company`, `is_opening`, `finance_book` remain unknown on legacy rows until replay; no invented defaults. Cancellation rows remain stored. Financial statements consume only uncancelled entries. PLE is still refreshed for existing consumers but never supplies statement amounts.
- Extend the existing ledger feed's GL persistence to a service-only, epoch-fenced page RPC, so overlapping sweep invocations cannot change the company source during completion. Preserve PLE behavior. A full-rescan candidate marks seen names; only after every source page and verification succeeds does completion reconcile disappearance of old GL names. Do not delete/update the previous published statement while rebuilding.
- `capture_erp_statement_source` creates immutable source-line rows from the completed **mirror**, with one transactional `INSERT … SELECT`, serializing numeric debit/credit as text. The saved chart/metadata belong to this generation. Subsequent paging always filters generation and orders source-line `id`; never page a changing live mirror for statement aggregation. Completed source lines cannot be edited. Do not mistake PostgREST's row cap for source exhaustion.
- Verify ERP source stability around the read: complete chart/settings/calendar fingerprints plus stable ordered ledger `(name, modified)` inventory (count and max alone are not sufficient). Verification is paged/bounded too. If source changes while building, catch up/restart verification, never mark a partial candidate complete. Keep the candidate resumable across ticks; sustained changes produce honest delay, not false freshness.
- Precompute every supported period pair from the captured, company-applicable fiscal calendar, for all three company statements and mapped-project P&L. Also compute finance-only unassigned P&L and separate project-total DTOs. No arbitrary date query, user-triggered posting, request queue, or user write to a read-model. A selected period must be in the server catalogue. A missing preceding fiscal calendar is unavailable, not a silently shortened comparison.
- Build indexed account/period/project buckets once, then roll up children once in reverse hierarchy order. Cache decimal sums/prefixes for repeated balance-sheet ends rather than scan ledger per account/project/period. Stage expected output in bounded pages on that generation, then switch all visible results in one transaction. CPU/deadline exhaustion leaves old results and resumes the candidate; never publish a prefix.

Use `search_path = public, pg_temp`, schema-qualified relations/functions and explicit EXECUTE grants. These signatures are introduced by B1 (claim/chart), B2 (page/capture), B4 (stage/publish/read). Lease renewal/takeover is inside claim; allocate epoch as the company's previous maximum + 1 under the company lock, including takeover. Resume source_complete work rather than claiming a competing generation. Status updates and collection use the same epoch fencing in the machine orchestration, not user-callable mutation RPCs. Stage at most 100 statement rows and 512 KiB serialized JSON per output chunk, keyed by chunk number on the candidate. Re-delivery must have the same digest; reject conflicting chunks. Publish accepts only `{chunkCount,rowCount,scopeKeys,digest}` and validates staged content against its server-derived expected scope manifest before replacement. Reject an oversized single statement envelope explicitly; never truncate its account rows. This bound is a transport budget, not a permission to drop a supported report.

The reader never accepts org/company/generation/ERP-project overrides. It derives the company from the activated binding and returns **one statement envelope in one SQL statement**, not a paged join across changing results. Catalogue and statement can race; reject a catalogue generation mismatch in the DAL and retry once, then give an honest retryable error. Detail JSON lives only on detail rows. Project-total **stored payloads and returned payloads** whitelist `income/expense/net`, period dates, currency, snapshot/time and delayed status. No chart, settings, filters, company amounts, party/voucher or raw ERP project name is stored on those rows (private filters column is empty there).

For caller-visible project checks use `exists(select 1 from public.projects p where p.id = project_id and p.org_id = public.auth_org_id())` under **security invoker**, so existing projects RLS participates. Do not infer project visibility from a PM title, manager assignment, config map membership or an all-org service query. Do not add a new assignment-only product rule. Company/detail target policies explicitly admit active Admin/Finance/Executive on accounts, both ledgers and statement detail. Add restrictive role conditions alongside the existing tenancy/employee constraints; preserve stronger independent constraints unless signed §2 requires a deliberate replacement. Direct grants, RLS, RPC EXECUTE and ordinary writes are all tested.

Example statement-total predicate (combined with org/active checks):

```sql
(public.auth_role() in ('Admin','Finance','Executive')
 or (view_kind = 'project_totals' and scope_kind = 'project'
     and public.auth_role() in ('Project Manager','Engineer')
     and exists (select 1 from public.projects p
                 where p.id = project_id and p.org_id = public.auth_org_id())))
```

Refresh status/catalogue metadata is read through a fixed **security-barrier, owner-rights view** `public.erp_financial_statement_availability` introduced in 0296, not a SELECT grant on machine generation metadata. Its definition explicitly filters `org_id = auth_org_id() AND is_active_member()` and the five allowed real roles; it exposes only org id, safe generation identity, IDR, applicable fiscal-calendar dates, last success time and a delayed boolean. Readable company label is null for project staff; no chart, ERP fiscal identifiers, filters, settings, counts, source fingerprint or errors are projected. Grant SELECT only on this view to authenticated; revoke PUBLIC/anon. The invoker catalogue RPC rechecks the requested project under caller projects RLS before using it. This view intentionally encapsulates machine-table access; it must not rely on owner-bypassed base-table RLS. Add cross-org/inactive/view-column tests to AC-003/004. It reports delayed if a newer failed/incomplete attempt exists or the published result missed the scheduled five-minute refresh interval. Retain original `as_of`; status time and result time are different facts. For absent snapshots this safe calendar projection supports unavailable, not zero totals. Snapshot project-total rows must also have empty filters and only safe readable provenance columns, so a direct SELECT cannot bypass the DTO whitelist.

`decimal.ts` represents exact signed base-10 coefficients/scales, using BigInt; addition aligns scales, subtraction is signed, and statement amount aggregation needs no division. Metadata zero-cutoff division uses exact decimal/rational arithmetic. Preserve raw ERP debit/credit numeric tokens before JavaScript Number conversion, including scientific notation; reject nonfinite/absent required money rather than coercing to zero. Add `decimalJson.ts` beside `ledgerFetch.ts`: JSON.parse's source-context reviver returns the raw numeric token for debit/credit, leaving flags/dates unchanged. Feature-test source-context support in both Node and the shipped Deno runtime; absent support fails this source profile closed (no float fallback). Extend `ErpRequestOptions` in `client.ts` with `responseNumbers?: 'default'|'ledger_decimal_text'` (default preserves all existing callers); apply the decoder to the already bounded response text only on successful ledger reads. Unit and Deno tests must prove large/long fractional raw tokens survive the actual transport. This confines decoding to the existing ERP client, not a parallel fetch implementation. Carry decimal text through Postgres JSON and DTOs. Quantize at **upstream function boundaries**, including `prepare_data`'s three decimals and opening-check precision, then render at captured ERP report precision. Record the Frappe rounding method and zero cutoff in metadata/fixtures. Do not round input lines to cents or whole IDR. Existing two-decimal helpers are not the parser for this path. Formatting must accept decimal strings at the captured precision without converting large totals through `Number`.

Rules to port as independently testable small functions (derive expected results from ERP, not these descriptions):

- Shared filters: selected company, uncancelled, blank/null plus default finance book, explicit project only when requested; no cost centre/other dimensions, no template or consolidation. Only leaf-account GL values; use current hierarchy for both periods. Sum roots for grand totals, never every displayed parent plus child. Union nonzero rows across the two columns, retaining ancestry.
- TB: with closing entries for opening/current; net opening/closing; groups shown; prior-year P&L opening off. With opening checks enabled, opening includes pre-start entries **or** `is_opening=Yes` (the upstream opening query is not simply `posting_date < start`), P&L opening is constrained to that column's fiscal year, and current activity excludes opening entries. When the captured setting ignores opening checks, apply its alternate date-only/current-period handling. Preserve all six fields separately, roll up, then apply upstream group netting and root totals. Do not truncate dates silently to another fiscal year.
- P&L: nonaccumulated, Income credit-positive and Expense debit-positive, exclude Period Closing Voucher even after close. Project variant adds only the mapped ERP project filter. Company includes everything; sum mapped projects + unassigned/unmapped remainder before rounding and prove equality at report precision. Reject ambiguous map inversions rather than allocating twice.
- BS: accumulate Asset debit-positive, Liability/Equity credit-positive to each end independently. Posted retained earnings stay in Equity. Provisional = assets − liabilities − posted equity. Reproduce the standard opening check at captured float precision and separate unclosed-earlier-years row; subtract that opening difference from provisional **only as upstream execute does**. No balancing entries, no extra retained-earnings row. A posted/cancelled close must not double-count profit.
- Run each column with its own fiscal-year context and filters, then join rows by stable synthetic/account keys under the same current chart. Do not treat a two-year comparison as one accumulated multi-year ERP report.
