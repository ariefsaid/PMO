## Design

### Outcomes and data flow

1. A `vendor_withholding_slip_bill` history child event is identified by its link ID, so its bill number must be resolved by a bounded repository lookup from that link to its joined `procurement_invoices` row (using `vi_number`, then reference number). `RecordHistory` then renders `Bukti potong bill link · VI-…`, not `Unavailable`; it neither exposes a UUID nor adds a per-event request. This is required even for creation events, whose generic history change payload has no captured invoice field.
2. Selecting **Open bill in case** carries the linked `invoiceId` with the existing target case/documents URL and `bupot` selection as the `bupotBill` query parameter. `ProcurementDetails` clears that transient target together with `bupot` on panel close and suppresses the destination detail panel’s usual arrival-heading focus while the bill target is present. The target `ProcurementLedger` gives its shared `DataTable` invoice row a stable DOM id and programmatically scrolls and focuses it once rows exist. This works after route mount/data arrival and at desktop or mobile reflow without inventing a second route.
3. Cosmetic findings are pinned at the lowest adequate layer: RTL/Vitest tests assert rendered text, locale copy, focus, retry, pagination, classes/tokens and formatting. The existing implementation already appears to meet F13 and F15–F21; tests must first demonstrate that removing the respective behavior makes them fail. F21 is pinned through the existing shared `entityForm.cancel` catalog key and the real English/Bahasa i18n provider; do not add a duplicate feature-local key.

### Reuse and constraints

- Reuse `DataTable`, `ListState`, `Button`, `ConfirmDialog`, `formatCurrencyCents`, the existing withholding hooks, and existing locale catalogs. Use only existing DESIGN.md utilities/tokens: `touch-target`/`min-h-11` for phone controls, `sticky bottom-0` and `bg-popover` for the reconciliation panel, `tabular-nums` for money, and normal focus-ring utilities. Do not add bespoke CSS, a new scroll helper, or new dependencies.
- The shared `DataTable` addition is deliberately minimal: an optional row DOM-target contract (id/tabindex) applied identically to its single desktop-table and mobile-card branches. It avoids a fragile document query for an arbitrary table cell and remains useful for future deep links.
- History name lookup remains one deduplicated, maximum-50-ID batch for visible events. Do not resolve names from raw IDs in JSX and do not change RLS or the server history API.
- Preserve all existing URL query parameters when local selection changes. Cross-case navigation owns only `bupot` and `bupotBill`; it must encode both values and still select the Documents tab.
