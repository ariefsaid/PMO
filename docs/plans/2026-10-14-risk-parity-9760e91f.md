# Issue #986 — Executive at-risk parity and KPI help

## Decision and design

Record **DD-RISK-1** in `docs/decisions.md`: the at-risk population is the active delivery set whose committed spend can grow against an active budget: `Ongoing Project`, `Won, Pending KoM`, `On Hold`, and `Internal Project`; `Close Out` is excluded. This extends the existing OD-W5-C2-A rule without changing its `>= 0.9` threshold or committed-budget basis.

The database remains the Executive aggregate authority. A new immutable, table-free SQL helper owns the SQL status taxonomy; `get_executive_dashboard()` calls it only from `active_committed`. The frontend remains the list-classification authority and retains `ACTIVE_PROJECT_STATUSES`; a source-level parity test plus pgTAP membership/aggregate proofs prevent the two representations drifting. There is no new table, API, index, RLS policy, or client-supplied `org_id`; the existing `security invoker` dashboard RPC and base-table RLS remain intact.

For linked KPI tiles, retain one destination link plus a separate sibling help button. Use the existing `Tooltip`, `touch-target`, global focus ring, 15px help glyph, card/border/radius tokens, and no new colors, layout, strings, or translations. The link remains the tile doorway; help becomes keyboard- and touch-reachable without a nested interactive.
