## Design confirmed from shipped seam

The shared seam already supplies the required architecture: the list page owns typed URL working-set state; `useListWorkingSet` serializes one replacement navigation per event; `useUrlSearchInput` keeps delayed search text local; `useListReturn` captures the canonical list path and `.main-scroll` offset, then calls React Router navigation with the validated context in `location.state`. The return hook requires `contentReady` to restore only after settled list content; it rejects non-canonical and tab/deep record targets. `listReturnNavigation(state, 'projects')` deliberately ignores Sales context, whereas the PipelineLens Sales link alone may read `listReturnNavigation(state, 'sales')`.

The intended feature therefore requires every adopting list's record-open path to call `openRecord()` rather than call `navigate('/module/:id')` or use an unadorned detail link. That is the only allowed way to carry the required return path and scroll position while retaining canonical record routes.

No data schema, repository, RLS, caching, dependency, or ADR change is implicated by this client-only seam.

## Stop condition — existing tests conflict with the requested behavior

The following existing assertions require a one-argument router navigation (or bare fallback navigation). `useListReturn.openRecord()` necessarily navigates with a second options argument containing validated router state. `useListReturn.returnToList()` necessarily navigates with validated clean return state, including an empty state object for direct fallback.
