# Microsoft 365 document linking — implementation plan

> **For agentic workers:** execute the checked tasks in dependency order using the repository's TDD discipline. Executor routing is fixed below, not selected by an individual builder. This document authorizes no build, push, PR or deployment by the planner.

**Goal:** Link Microsoft files/folders to the project register, procurement case register and budget-version evidence without copying bytes or transferring Microsoft's access authority to PMO.

**Spec:** `docs/specs/m365-onedrive-doc-linking.spec.md`, owner-signed 2026-10-14, including its revision and the two resolved Director decisions at the top. Those decisions supersede the older pending-question/status text deeper in the document. `docs/spikes/2026-08-18-m365-use-leg-live-probe.md` §Closure proves M1, not feature acceptance.

**Architecture:** Existing typed repositories → DAL → org-scoped registers/typed relations. A shared metadata-only picker uses the caller's `graph_proxy`; direct open never uses it. Controlled project-file freeze/checks run server-side inside the custody runtime, with generation-fenced DB commits and the narrowly scoped read-batch adaptation in `docs/adr/0085-m365-server-generated-read-batches.md`.

**Stack:** React 19, TypeScript, React Query, React Router 8, Vitest/RTL/jest-axe, Supabase/Postgres/pgTAP, Deno edge functions; no new package dependency.

## Global constraints and delivery

- Store metadata only. No Microsoft bytes, preview, Storage import, Graph content endpoint, write scope, folder creation, background timer/job, delta or watermark.
- One reference per register row; many rows per typed parent. Procurement `link` is its sole browser URL; legacy plain links are preserved. Budget links have no project ID or document lifecycle.
- Microsoft connection/default library never grants item access. Caller connection gates browse/checks, not committed reference display or direct open.
- Folder project rows remain **reference-only Draft**; no Issue/Approve/version/drift controls. Approved project files show the pinned version label and link the SharePoint **version-history page**, not latest-as-approved. Missing `sharepointIds` means unavailable.
- Source/actor/time are stamped/guarded server-side. Client never sends `org_id`, linker, link time, baseline, drift, check time or verification claim. Existing document `create(..., authorId)` signature remains compatible; DB remains authorship authority.
- Request ≤100 entries/page; explicit Load more; 300ms search debounce; immediate loading feedback (≤100ms); ignore superseded responses; contextual search ≤3 pages. No remembered location.
- Mutation UI uses real-role `usePermission`; impersonation is view-only. Reuse `document.create/edit`, `procDoc.create/edit`, `budgetLine.edit` + Draft, `integration.manage`.
- Synthetic fixtures only. Live evidence and any open security review detail stay private. Repository visibility was checked: PUBLIC. No client names, identities, tenant/site coordinates or credential instructions in public artifacts.
- Migration reserved: **`supabase/migrations/0292_m365_document_linking.sql`**; reverse: **`supabase/migrations/rollback/0292_m365_document_linking_down.sql`**. Do not use 0286–0288. Do not edit 0292 after phase 1 lands.
- All tasks are 2–5 minute **editing/test cycles** using the concrete patches/oracles below; lock wait, DB reset, reviews and external CI are elapsed gate time, not editing estimates. RED first, then GREEN. No red commit, skipped proof, copied production validator or weakened oracle.

## Design, deciding artifacts and reuse

1. **Storage choice:** keep `project_documents` and `procurement_documents`; add only typed `budget_version_document_links` and singleton `org_m365_document_settings`. This is the signed reversible data design, not a polymorphic attachment framework. `0001_init_schema.sql` supplies the parent/FK shapes; `0280_budget_version_editors.sql` decides editor history. Evidence writes must not touch that history.
2. **Mutation choice:** one ordinary INSERT/UPDATE/DELETE through RLS, with row triggers for stamps, atomic source collision, immutable parent and transactional audit. No select-before-write source check. This preserves AC-010's single UPDATE and source collision under concurrent callers. Internal server-only RPCs own verification/freeze; ordinary source writers cannot manufacture a clean signal.
3. **Lifecycle choice:** retain the current `transition_document_status` body from `0180_rpc_active_member_gate.sql`, including active-member, role, legality, approver≠author, transition audit and auto-Superseded parent. Add only linked-folder rejection and linked-file Issue routing. The service freeze RPC implements the linked Draft→Issued branch in one transaction; other transitions remain the existing RPC.
4. **Transport choice:** ordinary feature calls remain `graph_proxy` GET with separate `query`; do not widen `scopeCoversPath` to accept batch POST. Read-only internal batches are separately designed in ADR-0085 and reviewed before use. Extract connection resolution/refresh once from `proxy.ts`, preserving existing behavior. Browser request IDs never select someone else's connection.
5. **UI choice:** `DocumentsTab.tsx` owns the actual project table and Drawer. Procurement currently renders `pages/procurement/ProcurementLedger.tsx`, not a resurrected `ProcurementDocumentsSection`: put a focused case-reference section on the same Documents tab, alongside the existing financial ledger. Budget page uses `selected` version and `budgetLine.edit`; evidence goes beneath its selected version editor. Org defaults mount in existing `IntegrationsView.tsx`, separate from personal connection/setup.
6. **Version choice:** metadata-only list on every file target; history URL built on demand from Graph `sharepointIds.siteUrl`, `listId`, `listItemId`. Persisted pinned version remains a label, not a guessed Graph browser URL. If the pin is not found in loaded version pages, show "not found in loaded history" until all relevant pages are exhausted; only then say unavailable/pruned. Latest always remains a separate direct-open action.

### Performance, caching and failure semantics

Use `[orgId,userId]` in every Graph/connection query key and clear on account switch. Settings keys are org-scoped. Picker stores loaded pages only; no persisted Graph cache, secret-bearing body, raw next link or download URL in UI state. Request sequence numbers invalidate late responses on search, folder change and close; no `retry:true` on Graph queries. Single-flight within a picker, explicit retry on errors; no automatic repeated paging.

Batch up to twenty **displayed stale controlled files** per invoke. Two server-only nullable implementation fields, `ms_check_claim uuid` and `ms_check_claimed_at timestamptz`, provide a sixty-second lease; neither indicates successful verification. Claim RPC serializes same-row checks, excludes fresh checks (<24h), folders and Drafts; commit RPC fences claim + drive/item + baseline and rechecks actor/org. Network requests hold no DB lock. On failure leave successful `ms_last_verified_at` unchanged, persist `not_verified` for an owned claim, release it, and render the last successful time. Never interpret missing cTag as clean. These two fields join the full source-clear block and are null for folders/non-Microsoft states.

Indexes: `(org_id,budget_version_id,ms_linked_at,id)` on budget evidence, existing procurement/project parent indexes retained; partial `(org_id,ms_drive_id,ms_item_id)` on each register and ordinary identity index on budget links. No unique drive/item constraint: multiple references are permitted. `EXPLAIN` parent/identity queries in phase 1 against synthetic larger fixtures; millions of orgs remain index-scoped. No per-row connection reads, repeated lineage fetches or evidence→financial writes.

Reviewed failure text is §3.8 of the spec, with opaque `GRAPH_ERROR` → generic load-location hint, never invented deletion/licensing diagnoses. Invalid URL/facets fail before persistence/navigation. DB collision is `23514` with stable DETAIL `m365-source-collision`; preserve SQLSTATE and map safe copy, never render raw DB detail. Zero-row denied UPDATE/DELETE uses `assertWriteLanded` → 42501. Latest remains enabled on access/version/check failure.

```ts
export type MicrosoftItemKind = 'file' | 'folder';
export interface MicrosoftReferenceInput {
  drive_id: string; item_id: string; web_url: string;
  name: string; item_kind: MicrosoftItemKind;
}
export interface MicrosoftReference extends MicrosoftReferenceInput {
  linked_by: string; linked_at: string; last_verified_at: string | null;
}
export interface MicrosoftLibraryDefault {
  site_id: string; site_name: string; drive_id: string; drive_name: string;
}
export function validMicrosoftBrowserUrl(value: unknown): value is string {
  if (typeof value !== 'string' || /[\u0000-\u0020\u007f]/u.test(value)) return false;
  try { const u = new URL(value); return u.protocol === 'https:' && !!u.hostname
    && !u.username && !u.password; } catch { return false; }
}
// Item facet is checked as a presence test, not truthiness or extension.
export function itemKind(item: Record<string, unknown>): MicrosoftItemKind | null {
  const file = item.file != null; const folder = item.folder != null;
  return file === folder ? null : file ? 'file' : 'folder';
}
```

### 1.13 compare-and-set commit function core

Place the following complete function body in 0292; revoke all client execution and grant service_role as specified in 1.13. It is independently tested by the baseline/write-fencing cases.

```sql
create function public.m365_commit_document_check(
 p_actor_id uuid,p_doc_id uuid,p_claim uuid,p_drive_id text,p_item_id text,p_baseline text,
 p_name text,p_url text,p_content_tag text,p_success boolean) returns boolean
 language plpgsql security definer set search_path=public as $$
declare d public.project_documents%rowtype; v_org uuid; v_good boolean;
begin
 if p_actor_id is null then raise exception 'Cannot check this document.' using errcode='42501'; end if;
 perform public.assert_is_active_member(p_actor_id);
 select org_id into v_org from public.profiles where id=p_actor_id;
 select * into d from public.project_documents where id=p_doc_id for update;
 if not found or d.org_id is distinct from v_org or not exists(
  select 1 from public.projects p where p.id=d.project_id and p.org_id=v_org) then
  raise exception 'Cannot check this document.' using errcode='42501';
 end if;
 if d.source is distinct from 'onedrive' or d.ms_item_kind is distinct from 'file'
  or d.status='Draft' or p_claim is null or d.ms_check_claim is distinct from p_claim
  or d.ms_drive_id is distinct from p_drive_id or d.ms_item_id is distinct from p_item_id
  or d.ms_content_tag_at_issue is distinct from p_baseline then return false; end if;
 v_good:=coalesce(p_success,false) and p_content_tag is not null and btrim(p_content_tag)<>''
  and p_baseline is not null and btrim(p_baseline)<>''
  and p_name is not null and btrim(p_name)<>'' and public.m365_browser_url_valid(p_url);
 update public.project_documents set
  ms_item_name=case when v_good then p_name else ms_item_name end,
  ms_web_url=case when v_good then p_url else ms_web_url end,
  ms_drift_state=case when not v_good then 'not_verified'
   when p_content_tag=p_baseline then 'clean' else 'drifted' end,
  ms_last_verified_at=case when v_good then now() else ms_last_verified_at end,
  ms_check_claim=null,ms_check_claimed_at=null
 where id=p_doc_id;
 return true;
end; $$;
revoke all on function public.m365_commit_document_check(uuid,uuid,uuid,text,text,text,text,text,text,boolean)
 from public,anon,authenticated;
grant execute on function public.m365_commit_document_check(uuid,uuid,uuid,text,text,text,text,text,text,boolean)
 to service_role;
```
