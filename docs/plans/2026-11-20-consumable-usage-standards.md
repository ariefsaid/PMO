## Design summary
- Two new tables: `consumable_usage_standards` (the organisation's standards, soft-archived) and `work_order_consumable_plan_lines` (one row per work order and item: generated qty, optional adjusted qty and reason, basis jsonb, input fingerprint, generated by/at). The only writer of plan lines is a security-definer function; standards are written directly under RLS with column grants, as 0417 does for allowances.
- Pure function `computeConsumablePlan(lines, standards)` in TypeScript mirrors the SQL generation so the screen can preview and the unit test pins the maths (rounded once per item, longest-prefix match). The SQL function is the authority.
- "Out of date" is a fingerprint (hash over the work order's line ids and quantities and the matching active standards) stored at generation and recomputed at read.
- Material requests: `mrq_plan_quantity` gains the precedence of FR-CUS-011 and `mrq_plan_for` returns the source; `material_request_lines` gains a `plan_source` column. Over-plan reason behaviour is unchanged.
- ADR candidate: "the work-order consumable plan is a stored snapshot, not a live view" (OD-CUS-6), the reason being approvers judge requests against a figure that must not move under them. Write the ADR in the build PR only if the owner confirms.

## Migrations (numbers assigned by the Director; each with a rollback file; RLS + FORCE RLS; `stamp_org_id`)
- **Migration A** `consumable_usage_standards`: table (item_id, work_unit, boq_code_prefix, qty_per_unit numeric(14,6) > 0, margin_pct numeric(5,2) 0..100, archived_at), unique index on (org_id, item_id, lower(btrim(work_unit)), lower(coalesce(boq_code_prefix,''))) where archived_at is null, indexes (org_id, item_id) and (org_id, lower(btrim(work_unit))); `stamp_org_id` trigger; a check function that the item is active and same org (the `boq_allowance_ok` pattern); select for same-org active members; insert/update/delete by the stock-master rank rule; column grants. Rollback: drop table.
- **Migration B** `work_order_consumable_plan_lines`: table (work_order_id, item_id, generated_qty, adjusted_qty, adjust_reason, basis jsonb, input_fingerprint text, generated_by, generated_at, updated_at; unique (work_order_id, item_id); check adjusted_qty is null or reason present), FORCE RLS, select only to `authenticated`; functions `cus_plan_fingerprint(work_order_id)`, `cus_generate_plan(work_order_id)` (refuses Closed/Cancelled, project rule, set-based, keeps adjustments), `cus_adjust_plan_line(work_order_id, item_id, adjusted_qty, reason)`, `cus_get_plan(work_order_id)` (plan lines + "no standard" lines + out-of-date flag + prior quantity). Rollback: drop functions, table.
- **Migration C** (ships alone, approval path): replace `mrq_plan_quantity` to read plan line then allowance then 0; add `material_request_lines.plan_source text`; `mrq_plan_for` returns `plan_source`; `mrq_submit` snapshots it. Rollback restores the 1001 bodies and drops the column.
- Record history: attach standards to the existing record-history trigger (0260), not a new log.
