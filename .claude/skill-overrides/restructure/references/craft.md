## Relations to apply

- Group related label, value, metadata and action more closely than the next record, because whitespace must express belonging.
- Align reading edges and shared numeric columns with one grid template, because independent row flex layouts drift when values or labels change.
- Reserve a track for optional content rather than shifting its siblings, because comparisons need stable columns.
- Put real gaps between words and neighbouring boxes, because `space-between` can collapse to touching at a narrow width.
- Carry the inset around the bottom and corners as well as the top, because an evenly padded wrapper can still clip its content.
- Fit content, padding and border inside the control's box before centring, because flex alignment does not make an undersized control fit.
- Let a control hug its content while preserving PMO's hit target, because a stretched empty button separates affordance from meaning.
- Centre on the visible face of a glyph or label and keep related marks balanced, because a CSS box can be centred while its ink looks displaced.
- Keep numeric columns right-aligned and tabular; centre standalone digits optically only where the composition calls for it, because optical balance must not break comparison alignment.
- Separate almost-touching edges by a real spacing step or align them exactly, because near-tangents look accidental.
- Keep icons in fixed, non-shrinking slots from PMO's existing family, because mixed weight and squeezed glyphs destroy a shared visual language.
- Use PMO's title, figure, section, body and secondary type roles, because flattening all text to the legibility floor removes hierarchy.
- Use one foreground and one legible muted text role with existing status pairs, because quiet text still carries information.
- Keep an open trigger's state visually related to its overlay and restore focus on dismissal, because floating UI needs an intelligible origin and exit.
- Let content determine row height within the shared density tokens, because stretching rows to fill a void creates fat rows rather than useful density.
- Recheck insets after solving overflow, because widening a wrapper can merely move the imbalance to the opposite edge.

## You see → you do

| You see | You do, and why |
|---|---|
| A blank band below a short list | Pair content of similar height, contract or reflow the row; stretched emptiness is not calm |
| Words against a control's edge | Measure its content + padding + border, then fit the shared control; centring alone cannot add clearance |
| Numbers wandering between rows | Give header and rows one template; comparison needs a stable edge |
| A title drifting from its content | Restore the shared heading-to-content gap; the heading must visibly own its block |
| An isolated control in a wide empty box | Fit it to its content and group it with its job; empty width cannot explain an action |
| An icon that looks off-centre | Inspect the visible glyph beside its label; equal SVG boxes do not imply equal optical weight |
| A value without a noun on phone | Keep a visible label with the value; a distant legend cannot identify a scrolled card |
| Repeated warnings in neighbouring cards | Give the missing fact one scoped disclosure and remedy; repetition increases reading without adding meaning |

## Teaching pairs

- When a relation is disputed, capture bad/good pairs with identical data, state, scale and tokens and change one relation, because the cause must be visible.
- Label the exact difference and inspect at actual size and as a thumbnail, because a detailed close-up can conceal weak whole-screen hierarchy.
- Use pairs to teach a correction already observed, because a stylized example is not evidence of a newly claimed business defect.

## Boundaries

- Keep all real words, values, semantics and actions in working UI; bars as filler, faux content, decorative stages, cinematic crops and simulated cursors belong only to marketing illustrations.
- Use stageshow whole for landing-page product shots and demo animations, and taste's page run for the landing site, because that medium has a different job from an ERP screen.
- Keep app headings, accessible labels, readable type, keyboard paths and complete controls; illustration rules about tiny type or heading-free fragments do not apply to a real app.
