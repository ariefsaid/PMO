# Compose the whole screen

Read whole at step 4, after the floor and reference direction are frozen; taste's app-screen run is required background.

## Write before markup

- **Job and question:** write the person's decision in one line, because the screen needs an order the old cards cannot supply.
- **Finding:** allow ONE line of today's facts computed from the data, each clause linking to its place ("3 of 11 projects off track · 1 invoice 120 days overdue"), because a total without a consequence does not orient the reader.
- **Placement:** put it directly under the title or directly under the figures band and omit it when there is nothing to report; it never describes the page or how to use it, because explanatory page subtitles remain banned.
- **Owner direction:** preserve an explicit paired operations/finance brief at equal visual rank under its umbrella question, because the method must not demote half the owner's job.
- **Dominant answer:** name the biggest block and largest figure that answer the question, because a row of equally loud tiles supplies no first glance.
- **Next questions:** name every remaining block by the question it answers, because a block without a job spends space without helping a decision.
- **First screen:** at 1440×900 show every brief-named block's header and first rows or figure, because a headline plot must not push the product's work below the fold.
- **Long work:** cap overview rows and keep a labelled “View all” plus total, because first-screen coverage must retain access to the full register.
- **Primary job:** place its working control beside the answer within one click, because an overview is a working surface as well as a report.
- **Product substance:** use PMO's existing identity, scope and domain objects, because taste's “give it a face” step does not authorize a new shell, palette or font.

## One grid, with arithmetic

- Measure available width after the shell and gutters, then write the column sum in the brief and code comment, because viewport width is not canvas width.
- Use one panel gutter and shared alignment lines across rows, because unrelated grids leave orphan cells and dead edge strips.
- Choose spans from content and its job, because a short work queue stretched across a canvas separates its name from its amount.
- Balance row contents before equalizing frames, because matching bottom edges with a blank band is not composition.
- Pair a tall block with a useful stacked column or reflow the row, because `height: 100%` cannot manufacture substance.
- Keep chart keys beside their marks and content beside its heading, because a footer-pinned legend creates a hole inside the panel.
- Recompose when a screen accumulates more than about five fixes, because independent patches no longer express one hierarchy.

Example arithmetic (illustrative geometry, not PMO shell constants):

```text
Canvas = viewport − measured shell − left gutter − right gutter
12 tracks: 12c + 11g = canvas
8-track block + gutter + 4-track block = (8c + 7g) + g + (4c + 3g)
                                        = 12c + 11g = canvas
Phone: measure again; a task-first column is a separate composition.
```

## Data that tells the truth

- Render from existing authoritative selectors and repositories; repeated facts share a source, because separate view calculations drift.
- Record each figure's population, period, clock, currency, unit, tax basis, rounding and missing-data rule, because similarly named quantities may mean different things.
- Reconcile displayed parts, totals and deltas at their displayed precision; retain exact transaction/write values, because presentation rounding must not change accounting math.
- Keep known-zero, empty, missing, pending and failed distinct through tiles, counts, labels, chart lengths and exports, because a fabricated zero looks like a business fact.
- A chart of wholly unknown data joins the page's hidden-figures disclosure; partial charts draw known marks and state the gap once beside them, because silence can imply completeness.
- Keep genuine loaded zeros visible and bars at true zero length, because hiding zero also loses information.
- Use existing formatting rules for currency, dates and percentages; name comparison baselines and separate currencies, because arithmetic and visual comparison need shared units.
- Verify what “actual”, “budget”, “contract”, “earned” and “collected” read in source before drawing a comparison, because a matching shape does not make quantities equivalent.
- Use a time scale for dates, a shared magnitude scale for ranking and each whole's own denominator for proportions, because a pretty bar may otherwise say the wrong thing.
- Name each series directly or with a key generated from its marks; preserve short slices' identities, because hover and screen-reader labels alone do not identify visible colour.
- Draw graphics when the data and decision warrant them under screen-rules; keep the chart baseline, because calm must not become bare.
- Route a newly needed data/calculation contract to the Director before building it, because display work cannot invent a forecast or redefine a financial measure.

## States and phone

- Choose a busy record, long names, realistic ranges and partial data before composing, because a sparse fixture hides layout and truth failures.
- Let a filtered short list contract or pair it with similarly sized content, because a fixed empty frame is leftover space.
- Keep loading geometry close to settled content and retain good cached content on refresh, because state changes should preserve orientation.
- Compose the phone job with its evidence, labelled values and completion controls first, because stacking desktop blocks buries the work.
- Keep labels beside phone values after scrolling, because a detached header cannot name a card's bare numbers.
- Retain every floor item through a visible section or discoverable linked home, because narrow width changes arrangement rather than permission to delete.
- Test the actual error/retry, dirty leave, menu dismissal and Back journeys, because endpoint screenshots cannot prove recovery or retained work.

**Complete:** the brief contains the question, finding, block questions, grid sum, figure contracts and state/phone compositions; the running whole agrees with them and the frozen floor.
